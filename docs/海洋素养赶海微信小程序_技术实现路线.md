### 1.1 首版上线目标

首版聚焦“能学、能找、能拍、能记录、能安全使用”，只保留一条端到端主链路：

1. 海洋素养课程：图文、短视频和知识卡片，首批内容由后台录入；
2. 赶海点/科普场馆：按城市或用户选择的位置展示附近点位；
3. 行前安全提示与一套固定观察任务；
4. 拍摄与上传：调用相机或相册上传观察照片；
5. 个人记录：课程进度和观察照片；
6. 简易管理后台：课程、点位、首页配置和作品审核；
7. 隐私与未成年人保护：最小化收集、监护人同意、撤回授权、删除账号/数据。

### 1.2 首版明确不做

为确保 8 月 30 日前上线，首版不建议加入：

- 公开社区、私信、评论、直播和用户排行榜；
- 在线交易、付费课程和实物商城；
- 复杂题库、积分、勋章、班级和活动报名系统；
- 可视化页面装修、复杂工作流和多级运营权限；
- 自动发布用户照片；
- 将 AI 物种识别结果作为权威结论；
- 持续后台定位或轨迹记录；
- 无明确业务必要性的收货地址、身份证、学校班级等信息收集。

这些功能会显著增加内容审核、实名要求、未成年人保护和微信审核风险。若需要，可在上线后单独立项。

### 1.3 “访问用户地址”的定义

“地址”必须在需求评审时拆分为两种不同能力：

- **当前位置/选择地点（推荐）**：用于展示附近赶海点、天气和潮汐信息。采用 `wx.getLocation` 或 `wx.chooseLocation`，涉及 `scope.userLocation`，需在后台申请相关接口权限、在 `app.json` 声明用途，并写入《小程序用户隐私保护指引》。
- **微信收货地址（首版不推荐）**：采用 `wx.chooseAddress`，会返回收货人姓名、手机号和详细地址，敏感度和合规成本更高。只有确有邮寄奖品或实物履约需求时才申请，且必须由用户点击后调用。

本路线默认“地址”指用户主动授权的当前位置或主动选择的地点，不采集家庭住址。

### 2.2 容量假设（立项后 48 小时内确认）

“百万级用户”不能直接等同于“百万并发”。首版暂按以下规划假设设计：

- 可扩展目标：100 万注册用户；
- 规划峰值：10 万日活、300—500 API 请求/秒；
- 图片上传与内容分发走对象存储和 CDN，不经过应用服务器转发；
- 上线前压测目标：核心只读 API 至少在 200 请求/秒下保持可接受错误率和延迟，并验证可通过增加实例继续扩容；
- 若学校集中上课会产生更高瞬时流量，需根据学校数、班级数和上课时间重新计算峰值。

压测指标必须依据最终云资源规格修订；上述数值是工程规划假设，不是上线承诺。

## 3. 总体技术架构

### 3.1 技术选型

为适配 2—3 名开发者和 46 天工期，首版采用“微信原生 + 腾讯云托管服务”，避免自建 Kubernetes、消息中间件和复杂微服务：

- 小程序端：原生小程序 + TypeScript + WXML + WXSS；
- 状态与请求：轻量 Store、统一 API Client、请求重试与错误码；
- 后端：Node.js LTS + NestJS，部署到腾讯云 CloudBase 云托管或同等级托管容器；
- 管理后台：Vue 3 + TypeScript + Vite，仅实现必要 CRUD 和审核页面；
- API：HTTPS REST API，OpenAPI 文档；
- 主数据库：腾讯云 TDSQL-C/MySQL 或同等级托管 MySQL；
- 缓存与限流：首版优先使用 CDN、应用内短缓存和云网关限流；监控证明有需要后再接入 Redis；
- 文件：COS 对象存储，客户端临时凭证直传；
- 分发：CDN；
- 异步任务：首版使用云函数/托管定时任务处理审核和缩略图；流量增长后再引入消息队列；
- 部署：测试和生产两套托管环境，生产发布前使用独立预发布配置验收；
- 可观测性：云日志、APM、指标监控、错误告警和审计日志；
- 安全：云 WAF/API 网关限流、密钥管理、数据库备份、最小权限 IAM。

选择原生小程序而不是跨端框架，是因为当前目标只有微信端，且定位、隐私授权、相机/相册、审核适配均以微信原生 API 为准。若已确定 3 个月内必须同步上线支付宝或 App，再评估 Taro/uni-app。

### 3.2 逻辑架构

```text
微信小程序
  ├─ 课程与任务
  ├─ 地图与点位
  ├─ 相机/相册
  └─ 学习记录
       │ HTTPS
       ▼
CDN / 云 WAF / API 网关
       │
       ▼
CloudBase 云托管中的 NestJS API（无状态、可水平扩容）
  ├─ 用户与监护人同意
  ├─ 内容与学习进度
  ├─ 点位与活动
  ├─ 上传凭证与内容审核
  └─ 隐私请求与审计
       │
       ├─ MySQL：结构化业务数据
       ├─ CDN/网关：静态缓存与限流
       ├─ COS：图片、视频、课件
       ├─ 云函数：审核、缩略图等异步任务
       └─ 内容安全服务：图片/文本检测

简易管理后台 → 管理 API → 内容/点位发布、作品审核、数据删除
```

### 3.3 百万用户扩展原则

1. API 服务无状态，可按 CPU、延迟和请求量自动扩容；
2. 热门课程、点位列表和配置数据优先使用 CDN 缓存；出现数据库热点后再增加 Redis；
3. 图片使用客户端直传 COS，上传后异步压缩和审核；
4. 用户上传内容默认私有，不通过审核不得公开展示；
5. 数据库设置合理索引、读写超时、慢查询告警和连接池上限；
6. 学习事件与统计异步写入，避免阻塞主链路；
7. 生产发布使用灰度、快速回滚和数据库向前兼容迁移；
8. 以真实监控数据逐级扩容，不在 MVP 阶段提前建设复杂微服务。

## 4. 核心功能实现路线

### 4.1 登录与用户体系

- 使用 `wx.login` 获取临时 code，由后端换取 `openid`/`unionid`；
- 后端签发短期访问令牌，不把微信密钥放在小程序端；
- 默认允许游客浏览公开课程，只有保存记录、上传照片时才登录；
- 不默认索取昵称、头像、手机号或真实姓名；
- 年龄信息只收集实现监护人同意所需的最小信息；
- 未满 14 周岁进入需由监护人阅读并完成同意；
- 提供隐私政策、儿童个人信息保护规则、撤回同意、数据删除和账号注销入口。

### 4.2 定位与地点

调用链路：

```text
用户点击“查看附近”
→ 展示用途说明
→ 检查隐私协议状态
→ 申请 scope.userLocation
→ 调用 wx.getLocation / wx.chooseLocation
→ 仅向后端上传完成业务所需的经纬度或城市编码
→ 返回附近点位
```

实施要求：

- 在 `app.json` 中声明定位用途；
- 在小程序后台申请位置相关接口权限；
- 在《小程序用户隐私保护指引》中声明“位置信息/选择的位置信息”；
- 用户拒绝后提供手动选城市/点位的降级路径；
- 默认不保存精确轨迹；如仅需附近查询，处理完成后不长期保留精确经纬度；
- 日志不得记录完整精确位置与用户身份的直接组合；
- 点位数据需标注安全提示、开放时间、适龄说明和信息来源；
- 潮汐、天气等外部数据必须确认 API 授权、稳定性和数据时效，并显示“仅供参考，以官方预警为准”。

### 4.3 相机与相册

采用 `wx.chooseMedia`：

```ts
wx.chooseMedia({
  count: 9,
  mediaType: ['image'],
  sourceType: ['album', 'camera'],
  sizeType: ['compressed'],
  camera: 'back'
})
```

上传流程：

```text
用户主动点击上传
→ 隐私告知/系统授权
→ 选择相机或相册
→ 客户端校验数量、格式和大小
→ 后端发放短时 COS 上传凭证
→ 客户端直传私有桶
→ 云函数触发图片压缩、去 EXIF 和内容安全检测
→ 审核通过后生成可访问资源
```

安全要求：

- 不在页面加载时自动拉起相机或相册；
- 删除照片 EXIF，防止照片携带 GPS 等隐私信息；
- 对象存储默认私有，通过短时签名 URL 访问；
- 限制格式、大小、分辨率、上传频率和单用户配额；
- 图片经过机器审核，公开展示前增加人工复核能力；
- 数据库只存对象键，不存永久公开 URL；
- 用户可删除作品，后端同步删除派生图并记录审计事件。

### 4.4 内容与课程

- 课程采用结构化内容模型：专题、章节、知识卡片、媒体、题目；
- 管理后台支持草稿、审核、发布、下架和版本记录；
- 媒体资源通过 CDN 分发；
- 首页和课程目录可离线缓存最近版本；
- 课程内容由海洋专家审核并标记作者、审核人、版本和来源；
- 中国海洋大学名称、校徽、专家姓名和“背书”表述必须取得书面授权，不能仅凭合作意向使用；
- 安全知识、物种保护和禁捕规定需设置定期复核日期。

### 4.5 赶海任务与学习记录

- 任务包含适龄范围、准备清单、安全提示、观察步骤和完成条件；
- 学习进度采用幂等接口，避免网络重试造成重复记录；
- 现场任务先展示风险提示，不鼓励未成年人单独前往；
- 不公开精确的未成年人活动位置和时间；
- 勋章只作为学习激励，不做高强度排名或诱导分享；
- 行为事件异步采集，数据分析使用去标识化用户 ID。

### 4.6 简易管理后台

首版至少包含：

- 课程、首页配置和点位的新增、编辑、发布、下架；
- 素材上传；
- 用户作品机器审核结果和人工通过/驳回；
- 用户数据删除和注销工单；
- 管理员、内容编辑两种角色；
- 发布、下架、审核和删除等敏感操作记录操作者、时间和对象。

首批固定任务和安全提示可由研发随版本发布，不建设通用题库、流程编排器或可视化页面装修系统。

## 5. 合规、资质与微信平台要求

### 5.1 主体与品牌

- 优先使用中国海洋大学或经正式授权的单位主体注册，不建议用个人主体；
- 首日确认注册主体、管理员、主体负责人、对公材料和联系人；
- 校名、简称、校徽、专家身份、课程版权和图片版权均需书面授权；
- 名称、简介、Logo 和服务类目必须与实际功能一致；
- “中国海洋大学背书”应转换为可核验、经授权的具体表述，例如“内容由××单位指导”，最终用语由校方法务/宣传部门确认。

### 5.2 备案与类目

- 新小程序发布前必须完成小程序备案；
- 备案首周提交，主体负责人和管理员保持电话畅通；
- 收到工信部 12381 短信后须在 24 小时内完成核验；
- 若产品实质属于需前置审批的教育、出版、视听等业务，应先确认是否需要主管部门文件；
- “科普内容展示”与“在线教育培训”可能对应不同类目，不能只依据产品名称判断；
- 后端域名、HTTPS 证书、ICP 备案和小程序合法域名应尽早准备。

### 5.3 隐私与权限

- 在小程序管理后台配置《小程序用户隐私保护指引》；
- 隐私指引必须与代码实际调用的隐私接口一致，否则接口可能被禁用或提审被拦截；
- 使用微信隐私授权机制，调用前通过 `wx.getPrivacySetting` 判断状态；
- 在用户主动触发具体功能时再申请定位、相机或相册能力；
- 非必要权限被拒绝时，不得拒绝用户使用基本课程功能；
- 明确处理目的、方式、范围、保存期限、第三方 SDK、联系方式和删除渠道；
- 上线前完成个人信息保护影响评估，尤其是未成年人信息、精确位置和照片。

### 5.4 未成年人保护

- 不满 14 周岁用户的个人信息属于敏感个人信息；
- 处理其个人信息前须取得父母或其他监护人同意；
- 制定单独的儿童/未成年人个人信息处理规则；
- 只收集实现功能必需的信息，不以不同意非必要信息为由关闭基本服务；
- 提供监护人查询、更正、复制、删除和撤回同意渠道；
- 避免默认公开作品、精确位置、学校、班级和真实姓名；
- 若未来增加信息发布、即时通讯等服务，需重新评估真实身份信息、内容审核和未成年人模式要求；
- 正式上线前由熟悉互联网与未成年人业务的律师完成合规审查。

### 5.5 网络与安全

- 小程序只能访问后台已配置的合法域名；
- 请求、上传、下载使用 HTTPS，WebSocket 使用 WSS；
- 不使用 IP 地址或 localhost 作为生产接口地址；
- 注意小程序端 `wx.request`、`wx.uploadFile`、`wx.downloadFile` 的并发限制；
- API 实施鉴权、签名/令牌校验、重放防护、限流和参数校验；
- 密钥存储于云密钥管理服务，不写入代码仓库；
- 生产数据库开启自动备份和时间点恢复；
- 对高权限账号启用多因素认证并定期审计；
- 制定安全事件、内容风险和数据泄露应急预案。

## 阶段 2：Sprint 1—核心骨架（7 月 24 日—8 月 3 日）

目标：形成可真机演示的端到端版本。

- 小程序登录、游客模式、首页和课程模块；
- 简易管理后台登录、课程/点位维护和发布；
- 点位列表、手动选城市和定位授权；
- 相机/相册选择、临时凭证和 COS 直传；
- 学习进度与个人记录；
- 基础日志、错误码、监控和自动部署；
- 单元测试、API 测试和每日真机冒烟测试。

**关键节点 K3（8 月 3 日）：核心链路 Alpha。**  
必须在真机完成“进入小程序 → 学习课程 → 选择地点 → 拍照/选图 → 上传 → 查看记录”。

## 阶段 3：Sprint 2—安全、运营与完整体验（8 月 4 日—8 月 13 日）

目标：补齐上线所需能力，而不是继续扩展功能。

- 固定赶海任务和安全提示；
- 图片去 EXIF、压缩、内容安全检测和人工复核；
- 用户数据删除、撤回同意和账号注销；
- 简易管理后台作品审核和数据删除模块；
- CDN 缓存、网关限流、幂等、审计日志和备份；
- 空状态、弱网、拒绝授权和异常恢复；
- 校方专家完成首批课程内容审校；
- 完成隐私保护指引后台配置并核对接口扫描结果。

**关键节点 K4（8 月 13 日）：功能冻结，产生 Beta 候选版本。**  
8 月 14 日后只修缺陷、合规问题和审核问题，不新增功能。

## 阶段 4：测试、压测与上线审计（8 月 14 日—8 月 20 日）

目标：达到首次提审条件。

- 功能回归：核心链路、管理后台、数据删除；
- 真机兼容：主流 iOS/Android、不同微信基础库版本；
- 权限测试：首次允许、拒绝、再次开启、撤回授权；
- 隐私测试：隐私指引与代码调用逐项对应；
- 安全测试：越权、文件类型伪造、恶意上传、频率攻击、对象访问；
- 压力测试：热门内容、登录、进度写入、上传凭证；
- 容灾测试：数据库恢复、CDN 缓存失效、第三方 API 超时；
- 内容审校：科普准确性、安全提示、版权、校方表述；
- 完成发布说明、用户协议、客服与投诉渠道。

**关键节点 K5（8 月 20 日）：上线准入评审通过。**  
准入条件：备案/资质满足发布要求、P0/P1 缺陷清零、隐私核对通过、核心压测通过、内容授权齐全。

## 阶段 5：首次提审与整改（8 月 21 日—8 月 26 日）

目标：尽早提交，保留一次完整整改窗口。

- 8 月 21 日提交隐私指引/代码审核；
- 每日检查审核状态和平台反馈；
- 对名称、类目、权限说明、隐私、内容或交互问题当日分级；
- 24 小时内完成明确问题修复并重新提审；
- 保持生产配置冻结，只允许审核修复；
- 准备不依赖定位和上传的降级版本，以应对接口权限未通过。

**关键节点 K6（最晚 8 月 26 日）：代码审核通过。**  
若此时仍未通过，8 月 30 日上线风险极高，应由项目负责人决定是否移除高风险功能后再次提审。

## 阶段 6：发布、搜索验证与观察（8 月 27 日—8 月 30 日）

目标：完成正式发布并验证真实用户路径。

- 发布正式版，校验版本号、备案号、隐私指引和客服入口；
- 使用非开发者微信账号冷启动测试；
- 验证准确名称搜索、最近使用、二维码和分享卡片入口；
- 检查首页、课程、定位、相机/相册、上传和记录；
- 观察错误率、延迟、数据库、CDN、对象存储和内容安全任务；
- 进行小流量校方/学校用户试用，再逐步扩大；
- 形成上线验收记录、已知问题和回滚方案。

**关键节点 K7（8 月 30 日）：正式版可搜索、可打开、核心链路可用。**  
搜索收录和排序由微信平台控制；验收应以“使用准确名称能够检索到”为目标，不承诺模糊关键词排名。

## 7. 关键路径与红线

### 7.1 关键路径

```text
单位主体与品牌授权
→ 小程序注册/认证与名称
→ 备案、类目和接口权限
→ 隐私与未成年人方案
→ 核心功能开发
→ 真机/安全/合规测试
→ 首次提审
→ 驳回整改与复审
→ 正式发布
→ 微信搜索验证
```

任何一个前置环节延期，都不能靠后期加人完全追回。

### 7.2 上线红线

出现以下任一情况不得发布：

- 未完成依法需要的备案或资质；
- 未取得中国海洋大学相关品牌和内容授权；
- 隐私指引与实际权限调用不一致；
- 未满 14 周岁监护人同意机制缺失；
- 用户拒绝非必要权限后无法使用基本课程；
- 用户照片可被未授权访问或未审核即公开；
- 无数据删除、注销或投诉渠道；
- P0/P1 缺陷未清零；
- 无生产监控、备份或回滚方案。

## 8. 2—3 名开发者的分工

### 8.1 三名开发者（推荐）

- 开发者 A：小程序端负责人，负责页面、登录、定位、相机/相册、学习记录和真机兼容；
- 开发者 B：后端负责人，负责 API、数据库、COS、内容安全、权限、日志和云部署；
- 开发者 C：全栈与质量负责人，负责简易管理后台、CI、自动化测试、监控，并支援小程序端。

三人共同承担代码评审、每日冒烟和提审整改。任何核心模块至少由另一人完成一次交叉检查。

### 8.2 两名开发者（可行但必须继续降级）

- 开发者 A：小程序端 + 简易管理后台；
- 开发者 B：后端 + 云资源 + 自动化测试；
- 首批课程、点位和固定任务可通过受控数据脚本导入，后台只保留发布、下架、作品审核和删除；
- 小测验、勋章、运营活动、复杂统计全部移至上线后；
- 第 3 周起禁止新增需求，优先保证合规、真机测试和提审。

### 8.3 必需的非研发支持

开发者人数减少不等于可以省略以下职责，可由项目成员兼职或外部支持：

- 产品/项目协调 1 人：需求冻结、排期和外部流程；
- UI/UX 0.5 人：首周交付完整设计稿，后续只处理缺陷；
- 测试 0.5—1 人：从 8 月 3 日起持续真机回归；
- 内容运营与海洋专家 1—2 人：提供并审核首批课程和点位；
- 合规/法务 0.5 人：审核未成年人规则、隐私和授权文件；
- 校方接口人 1 人：品牌、内容和发布审批。

若上述非研发支持缺位，开发者将被迫承担内容、测试和审批工作，8 月 30 日上线风险显著增加。

## 9. 测试清单

### 9.1 功能与权限

- [ ] 游客可浏览课程；
- [ ] 登录失败可重试且不会重复建用户；
- [ ] 定位允许、拒绝、撤回后均有正确行为；
- [ ] 无定位权限时可手动选择城市；
- [ ] 相机和相册均可正常选择图片；
- [ ] 取消选择不会产生空记录；
- [ ] 大图、异常格式、重复上传和弱网上传被正确处理；
- [ ] 图片审核失败时用户得到合理提示；
- [ ] 用户可删除作品、学习数据和账号；
- [ ] 管理员越权访问被拒绝并记录日志。

### 9.2 兼容与性能

- [ ] iOS/Android 主流机型真机通过；
- [ ] 最低支持基础库版本验证通过；

- [ ] 所有点位和安全内容标明来源、审核人和复核日期；
- [ ] 客服、投诉、举报和未成年人保护联系方式可用。

## 10. 发布后 30 天工作

上线不代表百万用户准备完成。发布后应按真实数据演进：

1. 第 1 周：每日检查错误、审核队列、搜索可见性和用户反馈；
2. 第 2 周：根据慢查询、缓存命中率和上传失败率优化；
3. 第 3 周：完成一次容量复盘和安全扫描；
4. 第 4 周：根据学校试用数据决定是否开放更多城市和活动；
5. 达到容量阈值前完成数据库只读扩展、队列扩容和多可用区演练；
6. 新增社区、支付、AI 识别或收货地址前重新做产品、类目和隐私评估。
